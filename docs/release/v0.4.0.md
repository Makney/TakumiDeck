## Was jetzt geht

- **Terminal-Session ohne Claude.** Ein sechster Session-Typ „Terminal" spawnt direkt `pwsh.exe` (mit `powershell.exe`-Fallback) statt der claude-Binary — kein Modell, kein JSONL, kein Token-Verbrauch. Damit lässt sich eine schnelle Shell im selben Projekt-cwd öffnen, ohne eine Claude-Session zu starten.
- **Terminal-Verlauf überlebt den Resume.** Schließt man einen Terminal-Tab und resumet ihn später, schreibt TakumiDeck den letzten xterm-Buffer (Last-2000-Zeilen, 256-KiB-Cap) zurück, bevor die frische PowerShell ihren Prompt rendert. Vorher war das resumte Terminal optisch leer. Claude-Sessions bleiben bewusst unverändert (claude rendert seinen Verlauf beim `--resume` selbst aus der JSONL).
- **Modell-Liste selbst erweitern + automatisch abrufen.** Der Settings-Tab „Modelle" kennt jetzt `claude-opus-4-8` als Built-in und erlaubt eigene Modelle (ID + Anzeigename). Ein optionaler „Modelle abrufen"-Button fragt — sofern `ANTHROPIC_API_KEY` gesetzt ist — den `/v1/models`-Endpoint ab und schlägt neue IDs zur Übernahme vor. Ohne Key: freundlicher Hinweis auf manuelle Pflege statt Fehler.
- **Sidebar-Politur.** Aufmerksamkeits-Marker pro Projekt (orange = wartet auf Eingabe, gelb = unterbrochen/Fehler), Verlauf-Counter im Panel-Header und ein Rechtsklick-Kontextmenu für „Projekt entfernen". Dazu UI-Overhaul Block 1 (symmetrische 300-px-Sidebars, einheitliches 36-px-Header-Band), Datei-Browser-Filter mit Git-Status-Indikatoren und ein neues App-Icon + Brand-Logo in der Titlebar.

Für Detail-Einträge je Feature → [docs/CHANGELOG.md](../CHANGELOG.md) (Einträge zwischen v0.3.2 und v0.4.0).

## Bekannte Einschränkungen

- **App-Crash zwischen Tab-Sessions verliert den Terminal-Buffer.** Persist passiert im React-Cleanup-Pfad; ein hartes Force-Quit feuert den Cleanup nicht. Verfolgt in [TECH_SCHULDEN.md](../TECH_SCHULDEN.md) (Season 33) mit debounced-Live-Save als Auflösungs-Pfad.
- **Modell-Auto-Refresh nur mit API-Key.** Der `/v1/models`-Abruf braucht `ANTHROPIC_API_KEY`; Abo-/OAuth-Nutzer pflegen Custom-Modelle manuell (der Block weist darauf hin).
- **Kontext-Limits für Custom-Modelle laufen über die Per-Modell-Limit-Tabelle.** Das eigene `context_limit`-Feld wurde in v0.4.0 entfernt, weil es vom Verbrauch-Resolver nie gelesen wurde (siehe Code-Review MO1).
- **Offene Review-Punkte** sind in den `Release-Review v0.4.0`-Abschnitten von `OFFEN_DB.md`, `OFFEN_IPC.md`, `OFFEN_MODALS.md` und `OFFEN_PANELS.md` dokumentiert.

## Upgrade-Hinweise

- **DB-Migration nötig:** ja. Migration 0010 (`session_buffer_snapshots`) läuft automatisch beim Start — additiv, keine Bestandsdaten betroffen.
- **Settings-Migration nötig:** ja. Settings-Schema v2 → v3 setzt `custom_models: []` für Bestands-Settings automatisch; keine manuelle Aktion.
- **Setup-Änderungen:** nein.
- **Breaking Changes:** nein. `SessionType` um `'terminal'` erweitert und `custom_models` als Settings-Pflichtfeld sind additiv bzw. per Migration abwärtskompatibel.
