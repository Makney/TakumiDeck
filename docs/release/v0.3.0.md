# TakumiDeck v0.3.0

- **Datum:** 2026-05-19
- **Typ:** Minor *(Phase-2-Zwischenrelease, bündelt Season 25 – 29 + zwei Bugfixes; Phase-2-Roadmap noch offen → MAJOR bleibt bei 0)*
- **Phase:** Phase 2 ([→ Roadmap](../roadmap/PHASE2.md))
- **Vorgänger:** v0.2.1
- **Git-Tag:** `v0.3.0`

## Was jetzt geht

- **Terminal scrollt flüssig auch mit mehreren parallelen Sessions, hat eine eingebaute Such-Bar (`Strg+Shift+F`) und ein Rechtsklick-Menü.** Vorher stockten die Wheel-Events, wenn mehrere Tabs offen waren, und der Scrollback war auf 1000 Zeilen begrenzt. Jetzt: WebGL-Renderer als Primär-Pfad mit Canvas-Fallback bei GPU-Reset, TUI-Pattern-Poll pausiert für inaktive Tabs, `smoothScrollDuration: 0` (instant wie Windows Terminal / iTerm), 5000 Zeilen Scrollback, BEL-Pulse-Marker auf Hintergrund-Tabs, `Strg+1..9` für Direkt-Tab-Switch, `Strg+Mausrad` zoomt die Schriftgröße session-lokal (8…32 px), `Strg+Shift+L` räumt den xterm-Buffer (ohne den Shell-`Strg+L`-Pfad zu blockieren), Doppelklick markiert auch zusammengesetzte Pfade inkl. `:42:5`-Line-Col, ein Scroll-to-Bottom-Button schwebt rechts unten sobald man aus dem Live-Output rausgescrollt ist.
- **Der Diff-Viewer hat drei umschaltbare Modi und öffnet sich automatisch in Git-Projekten — und Editor + Diff aktualisieren sich live, wenn sich Dateien extern ändern.** Vorher musste man den Diff-Tab manuell anklicken und Tabs schließen+neu öffnen, damit externe Edits (z.B. durch einen Claude-Lauf) sichtbar wurden. Jetzt: Pillen-Toggle „Working Tree / Staged / Session" (Session-Modus zeigt alles seit dem Spawn der aktiven Session — egal ob in der Session geschrieben, zwischendurch committed oder noch ungestaged), Diff-Tab öffnet sich beim Projekt-Wechsel automatisch in Git-Repos und kann jetzt auch wieder zuverlässig geschlossen werden, ein chokidar-Watcher im Main pusht Live-Updates an Renderer (Diff refetcht, CLEAN-File-Tabs laden Inhalt nach, Dirty-Tabs bleiben unangetastet — lokale Edits gewinnen).
- **Das 5h-Fenster zählt jetzt echte fünf Stunden ab dem ersten Token, nicht bis zur nächsten vollen Stunde + 5.** Vorher: erste Nachricht 5:34 → Footer zeigte Ende 10:00 (nur 4h 26 min Restzeit). Jetzt: 5:34 → Ende 10:34, sauber fünf Stunden. Der Anker zieht aus der `messages`-Tabelle (minutenpräzise persistiert) statt aus den stundengranularen `usage_buckets`. Kein Restart, kein Backfill — der nächste `usage:window`-Aufruf liefert den korrekten Anker.
- **TakumiDeck prüft beim App-Start gegen die GitHub-Releases auf Updates und zeigt einen Banner mit explizitem Download- + Install-Trigger.** Im verpackten Build feuert ~5 s nach Window-Show ein `electron-updater`-Check. Wenn ein Update verfügbar ist, erscheint ein Akzent-Banner in der Header-Bar („📦 Update v0.x verfügbar — Download" → Live-Prozent während Download → „✅ Update bereit — Jetzt installieren"). Im Dev-Modus passiv. Manueller Re-Check im Settings-About-Tab.
- **`v*`-Tag-Push auf `origin/main` baut, signiert das `latest.yml`-Feed und veröffentlicht das GitHub-Release vollautomatisch.** Vorher lief Release über fünf manuelle `npm run make` / `generate-latest-yml.mjs` / `gh release create` / `gh release upload`-Schritte. Jetzt: `git push origin v<version>` triggert den GitHub-Actions-Workflow `.github/workflows/release.yml`, der auf `windows-latest` Pre-Check + Build + Asset-Upload in einem Lauf macht (8–12 min). Pre-Build-Verify-Gates fangen Version-Mismatch + fehlende Release-Notes vor dem teuren Build ab.
- **`settings.json` trägt ab sofort eine `schema_version` und Bestandsuser werden beim ersten App-Start auf die aktuellen Defaults gezogen.** Vorher konnten User von vor Sprint 8/9 weiterhin die „Wöchentlich · Claude Design"-Bar, `default_limit: 1_000_000` und 1-Million-Werte in `model_limits` mitschleppen (Anthropics altes Extended-Context-Beta, das für den Daily-Use als Default falsch ist). Die neue Migrations-Pipeline analog zum SQLite-Runner erkennt diese Drifts defensiv pro Feld — Custom-Werte bleiben unangetastet.

Für Detail-Einträge je Feature → [docs/CHANGELOG.md](../CHANGELOG.md) (Einträge zwischen `2026-05-18 — v0.3.0 — Phase 2 Season 25: Settings-Schema-Versionierung` und `2026-05-19 — v0.3.0 — Bugfix: 5h-Session-Block-Anker`).

## Bekannte Einschränkungen

- **Per-Tab-Font-Zoom (Strg+Mausrad) persistiert nicht.** Override lebt nur in React-`useState`, Settings-Hot-Update setzt ihn zurück. Drei Auflösungspfade in [TECH_SCHULDEN.md](../TECH_SCHULDEN.md) (Global-Override / Per-Project-Frontmatter / Per-Session-DB-Migration), Trigger bei erster echter User-Inzidenz „mein Zoom hält nicht".
- **Terminal-Buffer geht beim Resume verloren.** `SerializeAddon` ist seit Season 28 geladen, aber die Buffer-Persistierung selbst ist als Roadmap-Karte in [PHASE2.md](../roadmap/PHASE2.md) (Bereich Sessions) geparkt — offene Sub-Fragen (Buffer-Größe vs. Last-N-Zeilen, Persistenz-Trigger, BEL-Re-Senden unterdrücken) sind vor-strukturiert.
- **Terminal-Session ohne Claude** noch nicht implementiert. Als Roadmap-Karte in [PHASE2.md](../roadmap/PHASE2.md) (Bereich Sessions) geparkt mit allen Sub-Entscheidungen vor-strukturiert (pwsh.exe mit powershell.exe-Fallback, Title-Pflichtfeld, 6. Button in der Session-Buttons-Reihe).
- **Auto-Refresh überschreibt Dirty-Tabs nicht, zeigt aber auch keinen Warn-Marker.** Wenn eine externe Modifikation (Claude-Lauf, zweites Editor-Fenster) ein File ändert, das im EditorPane als Dirty-Tab offen ist, bleibt der Tab-Inhalt stumm beim alten Stand — kein visueller Hinweis, und ein Save vom Dirty-Tab überschreibt die externe Änderung leise. Auflösung mit drei Sub-Entscheidungen (Marker-Position + Action + Re-Sync-Strategie) in [TECH_SCHULDEN.md](../TECH_SCHULDEN.md) hinterlegt.
- **Code-Signing fehlt weiterhin.** Auto-Update funktioniert, aber Windows zeigt beim ersten Start die SmartScreen-Warnung. Im Settings-About-Tab als „Privat (kein Code-Signing)" beschriftet. Kein Trigger geplant — bewusste Single-User-Tool-Wahl.
- **Performance-Drift im 5h-Block-Hot-Path.** `messages(ts)`-Range-Query läuft auf einem Full-Table-Scan, weil die vorhandenen Indizes `ts` nicht als Leading-Column führen. Bei wachsender messages-Tabelle wird der 5h-Bar spürbar langsamer. Auflösung als P-3 in [`OFFEN_DB.md`](../code-review/OFFEN_DB.md): Mini-Migration 0010 mit `CREATE INDEX IF NOT EXISTS idx_messages_ts ON messages(ts)`.

## Upgrade-Hinweise

- **DB-Migration nötig:** ja — Migration `0009_sessions_start_commit_sha.sql` fügt `sessions.start_commit_sha TEXT NULL` hinzu (nullable, additive Spalte, kein Backfill). Läuft beim ersten Start v0.3.0 automatisch durch den Migrations-Runner, kein User-Eingriff.
- **Settings-Schema-Migration:** ja — `schema_version=2` wird beim ersten Read gesetzt. Defensive Drift-Detection pro Feld (Claude-Design-Bar entfernen *nur*, wenn alle fünf Default-Keys exakt passen; Sonnet-Label anheben *nur* bei exaktem alten Default-Text; `default_limit` clampen *nur* bei exakt 1_000_000; `model_limits` pro Modell gleich behandeln). User mit Custom-Werten oder bereits aktualisiertem Stand sehen keine Änderung.
- **Setup-Änderungen:** nein. Electron 41, Node 24, Vite 6 unverändert.
- **Neue Runtime-Dependencies** (werden beim nächsten `npm install` automatisch gezogen):
  - `@xterm/addon-webgl@^0.19.0` — WebGL-Renderer für das Terminal (Season 28).
  - `electron-updater@^6.8.3` — Auto-Update-Check + Download + Quit-and-Install (Season 26).
- **Breaking Changes:** keine. Migration 0009 ist additiv (`start_commit_sha` ist nullable, Bestand bleibt mit `NULL` weiter funktionsfähig — Session-Diff-Modus zeigt dann den Empty-State). Settings-Migration ist defensiv per Feld, Custom-Werte werden nicht überschrieben. Alle UI-Erweiterungen (Diff-Pillen, Terminal-Such-Bar, Bell-Pulse, Update-Banner, Settings-About-Block) sind additiv. Pre-1.0-`⚠ Breaking`-Banner daher nicht gesetzt.
